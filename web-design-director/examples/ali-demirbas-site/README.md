# Example: alidemirbas.com.tr

The one full worked instance behind this methodology's evidence base. Every
`[VALIDATED IN PROJECT]` and `[OBSERVED]` status tag in `methodology/`
traces back to something that actually happened on this site — a real
regression, a real fix, a real experiment.

**Register composition:** predominantly PORTFOLIO/PERSONAL (the site's own
identity), with PRODUCT MARKETING sub-pages for each open-source Lab
project, and UTILITY-interactive pages for its calculator tools — a live
example of registers.md's hybrid rule (page register may differ from site
shell register) in practice across one real site.

**What's in this folder:**

- `site-constitution-instance.md` — this project's actual DESIGN.md content
  (tokens, type ramp, the mono-rail signature, the one-dark-plate rule) —
  what `templates/DESIGN.md` looks like once filled in for a real project.
- `incident-log.md` — the provenance behind the anti-pattern and QA-detector
  citations in `methodology/` that reference this project specifically (a
  commit hash, a rejected 19-box layout, the padding-seam detector's
  known-good/known-bad scores) — kept here so an external reader can see
  what those numbers refer to without needing this project's own repo.

**What this example does not cover:** every register this taxonomy names.
The taxonomy's `[PLAUSIBLE]` tag on registers.md is honest specifically
because this is the only real project behind it — COMMERCE, EDITORIAL, and
a from-scratch PREMIUM BRAND build have no worked example here yet. The
strongest next addition to this repository is a second example from one of
those registers.

This example is read-only reference material — it documents what this one
project did, not a template to copy onto a new project (that would be
exactly the "copied scaffolds across projects" anti-pattern this
methodology names and rejects).
