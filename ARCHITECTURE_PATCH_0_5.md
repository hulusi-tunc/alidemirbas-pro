Applied 2026-09-01, before Gate 1. No canonical journey file was changed in this patch.

| Item | What changed | Where in the ADR |

## Gate 0.5 acceptance — checked

1. Corpus totals consistent: 283 / 135 / 68 / 67 / 24 / 124 — every downstream reference updated.
2. The three gold-standard specs are representable by the final schema with no prose-only exception (verified again while patching: optional `gatedBy`, `relativeTo: attribute`, ordered `channelRoles`, touch `priority`, `localCap.appliesTo`, `businessOutcome.observationScope`).
3. Checkout uses ordered channel roles: t1 `["low-friction", "persistent"]`, t2 `["persistent"]`, t3 `["persistent"]` (urgent only through the optional-strategy preset override).
4. FIN-134 fits the cap model: two mandatory touches outside a `non-mandatory` cap of one discretionary reminder.
5. SCH-266 has touch-level priority: default *service*, at-risk touch *service-critical* with reason.
6. SCH-266's `attendance_recorded` is legal: `handoff-chain [SCH-178]`, window `through-handoff` until `service_completion_recorded`.
7. FIN-134's `obligation_satisfied` is legal: `handoff-chain [TIM-65]`, window `through-handoff` until `grace_period_ended`.
8. Every taxonomy statement the validator relies on is typed (`RuleStatement`, `Config.default.basis`, `Touch.label`, `ChannelStrategy.label`).
9. No field has two sources of truth: the ownership table in §G lists one owner per concern; duplication is a validator error.

## Amendments made while authoring the Gate 2 reference journeys

| Amendment | Why | Where |
|---|---|---|
| `Touch.after?: string` — progression is an explicit reference to the touch this one follows; absent means "reached from the entry". Array order is reading order only. | FIN-134's corrective request and its offer-alternate are *alternative* first touches on two branches of one classification, not a sequence; a position-based path rule rejected a correct graph. | `types.ts`, `vnext-rules.mjs` (`orch_path_broken` walks `after`), ADR §F |
| `journeyOutcome.type` gains `"exit-or-handoff"` | FIN-134 has done its job when the obligation is recovered (an exit) *or* its consequence is owned elsewhere (three handoffs); SCH-266 likewise. One type could not name both. | `types.ts`, validator |
| `touch_optional_as_canonical` now fails only when a CANONICAL_RULE touch *depends on* an OPTIONAL_STRATEGY touch through `after` links | FIN-134's mandatory discharge confirmation is listed after the optional reminder but does not depend on it. | `vnext-rules.mjs` |
| `simultaneous_without_reason` is a warning (`simultaneous_review`) for touches that share a gate | Two touches on exclusive branches of one condition (SCH-266's at-risk notice and ordinary reminder) share a gate and are never simultaneous; the machine cannot tell exclusivity from simultaneity, so it asks. | `vnext-rules.mjs` |
