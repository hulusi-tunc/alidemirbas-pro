## TIM-274 — Grace Period Recovery

- Canonical ID: `TIM-274`
- Slug: `grace-period-recovery`
- Display name: Grace Period Recovery
- Canonical name (chain form): Grace period entered → recover before it ends → restored or lost
- Source route: `/lab/customer-journeys/grace-period-recovery`
- Category: Time, deadlines, expiry & temporary states
- Goal: expiry-renewal
- Channels: email, sms
- Surface: customer (communicating)

**Purpose**: Tell the holder that validity has lapsed into a bounded period with reduced function, what still works, when that period ends and the one route back - so grace is a state they are in knowingly rather than one they discover when something stops.

> Tell the holder that validity has lapsed into a bounded period with reduced function, what still works, when that period ends and the one route back - so grace is a state they are in knowingly rather than one they discover when something stops.

### Trigger
- Event: `grace_period_started`
- Meaning: an authoritative grace state recorded against the entity after its primary validity ended; a fixed end date for that grace period; a recorded condition that would recover the active state
- Not enough on its own: a validity date that is merely approaching; a failed renewal attempt with no grace policy applied to it
- Requires: an authoritative grace state recorded against the entity after its primary validity ended; a fixed end date for that grace period; a recorded condition that would recover the active state
- Source: authoritative

### Entity
- Scope: the entity whose primary validity ended, plus the fixed end of the grace period placed on it
- instance: entity_ref + grace_period_id · one-active-per-key

### Who enters
- an authoritative grace state recorded against the entity after its primary validity ended
- a fixed end date for that grace period
- a recorded condition that would recover the active state
- no instance of this journey is already open for the the entity whose primary validity ended
- hard gates (GLB-31) allow communication for this purpose

### Suppressed when
- [canonical rule] Grace is never announced before it is authoritatively recorded. A warning about a lapse that has not happened is a different journey and belongs before this one.
- [canonical rule] The message names what still works, not only what stopped.
- [canonical rule] One message before the window closes, never two.
- [canonical rule] The window does not move because somebody read a message. Engagement is not recovery.
- [canonical rule] Both endings are stated. Silence after a recovery and silence after an expiry are indistinguishable to the person living in the window.

**Channel roles** (recommended default)

### Stops when
- [success] recovered inside the window (re-entry: a later lapse opens a new grace period and a new instance)
- [invalid-state] grace ended by termination before its window closed (re-entry: an entity reinstated and later lapsing again qualifies afresh)
- [timeout] window closed unrecovered (re-entry: a validity granted later starts a fresh lifecycle; re-entry here needs a new lapse)

### Configure
- `grace_period.grace` [config required] (reminder-before-attribute): configure grace_period.grace — The point inside the window at which one further message can still be acted on.
- `grace_period.final` [config required] (attribute-bound): configure grace_period.final — After the last call the instance waits until the grace end itself; recovery before it is confirmed, and its passing is the loss.
- `grace_period.touches` [recommended default]: 3 — Every touch runs against a budget fixed when the instance opened; the budget is the plan's own length, and no touch is repeated because nothing could tell whether it arrived.
- `grace_period.cooldown` [recommended default]: none — This journey is per the entity whose primary validity ended; a later instance concerns a different the entity whose primary validity ended and no cooldown applies between them.

### Reusable rule
A grace period only helps somebody who knows they are in one, when it ends, and the single thing that ends it early.

### Entity (notes)
- the entity whose primary validity ended, plus the fixed end of the grace period placed on it
- One lapse, one grace period. A second lapse after a recovery is its own instance with its own window, and a window never inherits time from the one before it.

### Distinct from
- TIM-65 (Grace period entry → temporary continuity → recover or terminate) — TIM-65 grants the grace state, records which capabilities continue and decides what happens when the window closes. This journey is what the holder is told across that window, and it sends nothing until that state exists.

### Guardrails
1. Grace is never announced before it is authoritatively recorded. A warning about a lapse that has not happened is a different journey and belongs before this one.
2. The message names what still works, not only what stopped.
3. One message before the window closes, never two.
4. The window does not move because somebody read a message. Engagement is not recovery.
5. Both endings are stated. Silence after a recovery and silence after an expiry are indistinguishable to the person living in the window.
