**Purpose**: Work out which version actually governs, and explain the conflict rather than deleting it.

### Reusable rule
Document reconciliation restores a single authoritative version lineage by explaining conflicts rather than overwriting or deleting inconvenient historical records.

### Entity (notes)
- the document lineage and every conflicting record claiming to be part of it
- Every conflicting record is evidence. Deleting one to tidy the state removes the proof of what anybody relied on.

### Distinct from
- INT-118 (Integration reconnect → backfill → deduplicate → reconcile) — A generic sync conflict asks which record is newer. This asks which version is authoritative, which turns on issuance authority, lineage and effective semantics - and it must additionally establish which version each signature actually binds to, a question recency cannot answer.

### Guardrails
1. The newest file is not automatically the authoritative version.
2. Conflicting evidence is never deleted to fix the state.
3. Signature validity is checked against the exact version.
4. Reconciliation preserves lineage and prior use.

### Technical logic (graph, 14 nodes)
- **t.inconsistency** [trigger] (entry, evidence: authoritative)
  - Event id: `document_version_inconsistency_detected`
  - Document version inconsistency detected
  - evidence: authoritative
  - requires: a material inconsistency - different content under one identifier, an incorrect version distributed, a signature attached to the wrong version, a local copy differing from the authoritative record, several versions claiming current status, or a missing amendment link
  - not enough on its own: two versions that differ by design, such as a draft alongside its issued form
  - not enough on its own: a formatting difference between two renderings of the same version
  - -> a.collect (node)
- **a.collect** [action]
  - Collect the document ids, the version ids, the content with its hashes or references, the issuance times, the signature evidence, the effective dates, the lineage, and the authority or source behind each record
  - writes document_log (append)
  - -> c.identifiable (node)
- **c.identifiable** [condition] (2 branches)
  - Is the authoritative version deterministically identifiable?
  - -> a.authoritative [It is]: lineage, issuance authority and effective semantics together single out one version (node)
  - -> a.cannot [It is not]: two or more versions have equal claim, or the lineage is broken (node)
- **a.authoritative** [action]
  - Record which version is authoritative and why, preserving every conflicting record alongside it. This is a deterministic resolver applying c.identifiable's own criteria - lineage, issuance authority and effective semantics - never a human judgment call at this step; the resolver having already singled out one version is what makes this action reachable at all, which is why an inability to do so routes to h.review's human decision instead of arriving here. Conflicting evidence is not deleted to tidy the state - it is the only proof the conflict happened, and the only way to work out afterwards what anybody actually relied on
  - writes document_log (append)
  - -> c.signature (node)
- **a.cannot** [action]
  - Record DOCUMENT_RECONCILIATION_REQUIRED and change nothing. The newest file is not automatically the authoritative version - recency is a property of a filesystem and authority is a property of an issuance, and picking the newer one is how a superseded draft becomes the contract
  - writes document_log (append)
  - -> h.review (node)
- **c.signature** [condition] (2 branches)
  - Is any signature bound to a version other than the authoritative one?
  - -> a.sig-invalid [One or more are]: a signature was made against a version that is not authoritative (node)
  - -> c.acted [All bind correctly]: every signature is against the authoritative version (node)
- **h.review** [handoff]
  - Decision request → validate → route, reject or hold
  - Detail: a conflict where the authoritative version cannot be safely determined
  - carries: every conflicting record with its hash, issuance, signatures, effective dates and lineage
  - carries: the explicit fact that nothing was deleted, corrected or promoted - the conflict is preserved intact for the decision
  - -> DEC-181 (journey)
- **a.sig-invalid** [action]
  - Record that the signature does not bind to the authoritative version, without discarding the signature. It is valid evidence for the version it was made against and for no other, however similar the content of the two looks
  - writes signature_log (append)
  - -> h.resign (node)
- **c.acted** [condition] (3 branches)
  - Was a non-authoritative version distributed or acted upon?
  - -> a.correct-distribution [Distributed, not acted upon]: a recipient holds the wrong version and has done nothing on it (node)
  - -> a.preserve-history [Already used for a business action]: something was decided, paid, granted or performed on the wrong version (node)
  - -> x.reconciled [Neither]: the conflict was internal and nothing left the system (node)
- **h.resign** [handoff]
  - Signature request → await signatures → signed, declined or expired
  - Detail: signatures that bind to a version other than the authoritative one
  - carries: the authoritative version and which signatures are missing against it
  - carries: the explicit fact that the existing signatures stand as evidence about their own versions and are not transferred
  - -> DOC-215 (journey)
- **a.correct-distribution** [action] (execution: communication)
  - Redistribute the authoritative version, saying explicitly what changed and which version it replaces. A silent correction leaves the recipient holding two documents and no idea which one counts, which is worse than the original error
  - writes document_log (append)
  - -> x.reconciled (node)
- **a.preserve-history** [action]
  - Preserve what was done and under which version it was done. The action happened - what to do about it is a separate question with its own authority, and rewriting the record to show the right version leaves an effect with no cause
  - writes document_log (append)
  - -> h.remedy (node)
- **x.reconciled** [exit]
  - authoritative version established; conflicting records preserved and explained
  - Detail: a further inconsistency in this lineage is assessed with this reconciliation as part of its evidence, which is why none of it was deleted
- **h.remedy** [handoff]
  - Remedy selection → resolve obligation → financial handoff if needed
  - Detail: a business action taken on a non-authoritative document version
  - carries: what was done, under which version, and what the authoritative version says instead - conflict_id stands in for REM-157's obligation_id
  - carries: the explicit fact that the history is preserved intact - the remedy addresses the consequence rather than the record
  - carries: a fresh issue_id, minted at this handoff and deterministically derived from conflict_id - DOC-220 has no issue concept of its own, so REM-157's instance is opened here rather than carried
  - -> REM-157 (journey)
